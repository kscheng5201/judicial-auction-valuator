# Data Sources

Source-by-source integration notes. See `docs/PROJECT-BRIEF.md` §4 for
the high-level rationale (why "open data" in Taiwan is rarely a live
API). Every source added to `src/ingestion/` should get an entry here
before or alongside the code that integrates it.

## Judicial Yuan auction announcements (司法院法拍公告)

- **Category**: (c) unstructured HTML/JSON — scraping only, no
  published API.
- **Integration**: `src/ingestion/judicial_yuan/`.
- **Endpoints used** (see `config.py` for current URLs):
  - `WHD1A02.htm` frameset → establishes session cookies.
  - `WHD1A02/V1.htm` (search form) → `_csrf` token.
  - `WHD1A02/V2.htm` (results frame) → `token` field.
  - `WHD1A02/QUERY.htm` → JSON listing data, paginated. `saletype`
    distinguishes upcoming auctions (`1`, `4`) from completed/hammer-price
    records (`5`).
  - `WHD1A02_DETAIL/V1.htm` → per-listing detail JSON (`para` key).
  - `WHD1A02/DO_VIEWPDF.htm` → streams the auction notice PDF
    (`filenm` path from the listing record).
- **Raw snapshot**: PDFs are saved under `data/raw/judicial_yuan/pdfs/`
  (gitignored — regenerated by re-running the crawler, not checked
  in). The full raw JSON response for every listing and detail call is
  also stored as-is in the `auctions.raw_json` /
  `auction_details.detail_raw_json` columns (see
  `src/ingestion/judicial_yuan/db/schema.sql`), so parsing logic can be
  re-run against what was actually received without re-fetching.
- **Rate limiting**: `JUDICIAL_YUAN_REQUEST_DELAY` (default 0.8s)
  between requests. Do not parallelize aggressively against this
  endpoint — see repository-level convention in `CLAUDE.md`.
- **Fragility**: no public API means no stability guarantee on field
  names or response shape. `pipeline/upsert.py` defensively checks
  multiple casings of each field (e.g. `crmyy`/`CRMYY`) because the
  site has been observed to vary this. `scripts/diagnose_judicial_yuan.py`
  is a standalone live probe for when the parser starts silently
  returning empty/partial records.
- **Reliability on a desktop scheduler**: this crawler runs unattended
  on a local machine, so the dominant failure mode is the machine not
  being connected to the internet at the scheduled fire time, not a
  site format change. Three layers handle this:
  1. `retry.py` retries any network call with exponential backoff
     (`JUDICIAL_YUAN_RETRY_MAX_ATTEMPTS`/`_RETRY_BASE_DELAY`) — absorbs
     brief blips within a single run.
  2. `pipeline/upcoming.py` / `pipeline/historical.py` track the last
     *successful* run per pipeline (`crawler_runs`, via
     `get_last_success_finish`) and widen the query window back to
     that date if it's older than the default lookback — so a run
     that failed outright, or never fired, gets its gap covered by
     the next successful run instead of silently losing that window.
  3. `scripts/schedule_judicial_yuan_crawler.py` sets a generous
     `misfire_grace_time` (`JUDICIAL_YUAN_MISFIRE_GRACE_SECONDS`,
     default 6h) with `coalesce=True`, so a job missed because the
     machine was asleep still runs once it wakes, and failures that
     still escape (e.g. the database itself being unreachable) trigger
     `notify.send_alert` rather than failing invisibly.
- **Licensing**: publicly published court auction announcements;
  no terms-of-use restriction identified as of this writing. Re-check
  before adding bulk/parallel fetching.

## Sources referenced in the project brief but not yet integrated

The following are listed in `docs/PROJECT-BRIEF.md` §4 as planned
sources. Each needs its own entry here (category, endpoints, rate
limits, licensing) at the point it's actually integrated:

- Enforcement Agency (行政執行署) auction listings — scraping only.
- Taiwan real-estate price registry (實價登錄, MOI) — periodic batch
  file release, not a live API.
- TDX (Transport Data eXchange) — genuine REST API, OIDC client
  credential auth.
- OSM Overpass API — genuine open API.
- Google Places API — commercial API; check usage terms before using
  for a paid product.
- Municipal open data portals — mixed API/file-download, coverage
  varies by city.
- Address/geocoding services (TGOS, municipal land offices, OSM
  Nominatim, Google Geocoding) — mixed; needs empirical testing
  against cadastral-style addresses (段/小段/地號).
