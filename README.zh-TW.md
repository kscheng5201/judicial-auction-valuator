# 法拍屋估價與查詢系統

[English README](README.md)

> ⚠️ 專案開發中。本文件為初步專案說明，會隨開發進度更新。

## 專案簡介

台灣的法拍屋（司法院法院拍賣不動產）公告資料是公開的，但這些資料只是「原始清單」，
並沒有被整理成方便投資決策使用的形式。買方很難系統化地判斷：

- 這間法拍屋的合理出價區間大概是多少？
- 公告上列出的各種條件（屋齡、樓層、有無電梯、有無點交、權利範圍等），
  哪些是加分項、哪些是扣分項，影響程度各是多少？
- 房屋銷售網站常標榜「距離捷運站 5 分鐘」，但這通常是**直線距離**，
  如果中間隔著河流、鐵軌、快速道路，實際走路或通車時間可能是好幾倍——
  這種「假捷運宅」話術該如何被識破？

本專案的目標，就是把法拍公告資料、政府開放資料、交通與生活機能資料整合起來，
透過歷史成交案例回推出一套**可解釋的評分模型**，讓使用者不只拿到一個出價數字，
而是清楚知道「這個數字是怎麼算出來的」。

## 核心功能方向

1. **資料整合**：彙整司法院法拍公告、實價登錄、捷運/鐵路站點、生活機能點位、
   嫌惡設施等多方資料來源。
2. **距離真實性校正**：計算「直線距離」與「實際步行路徑距離」的落差比值，
   當落差過大時（代表中間有地理阻隔），會明確標示警示，而不是照單全收
   賣方標榜的距離優勢。
3. **可解釋評分模型**：以歷史法拍成交價與正常市場成交價為基礎，
   反推屋齡、樓層、電梯、點交狀態、交通與生活機能等各項因子的加權係數，
   讓每一項加分/扣分都有明確的資料依據，而不是黑盒模型丟出一個數字。
4. **出價建議區間**：不提供單一「正確答案」式的數字，而是給出保守出價、
   建議出價、積極出價三種區間，並附上該區域歷史案例多寡所反映的信心水準。

## 專案架構

系統拆成四層，各自可以獨立演進：

```
資料蒐集層 → 資料強化層 → 評分/定價模型層 → 應用層
```

- **資料蒐集層**：從各資料來源取得原始資料。司法院法拍公告目前沒有公開 API，
  需以爬蟲方式處理；實價登錄則是定期釋出的批次檔案，而非即時查詢介面；
  交通資料（TDX 運輸資料流通服務）則有正式的 API 可串接。
- **資料強化層**：把原始公告轉換成結構化特徵，包含地址地理編碼、
  距離真實性校正、生活機能評分、嫌惡設施風險標記等。
- **評分/定價模型層**：以可解釋的加權迴歸模型為第一階段基礎，
  未來視資料量再考慮疊加非線性模型做微調。
- **應用層**：提供使用者查詢、瀏覽、比較物件，並呈現出價建議與判斷依據。

完整的架構理由、資料源分類細節、評分模型設計，請參考
[`docs/PROJECT_BRIEF.md`](docs/PROJECT_BRIEF.md)（英文技術文件）。

## 資料來源說明（簡要）

| 資料 | 取得方式 |
|---|---|
| 司法院法拍公告 | 網頁爬蟲（無公開 API） |
| 內政部實價登錄 | 定期批次檔案下載 |
| 捷運/鐵路站點資料 | TDX 運輸資料流通服務 API |
| 生活機能點位 | OpenStreetMap / 地圖服務 API |
| 嫌惡設施、地籍圖資 | 各縣市開放資料平台，型態不一（部分 API、多數為檔案下載） |

## 專案定位與限制

- 本系統提供的出價建議為**決策輔助參考**，不是正式估價，也不保證得標。
  法拍屋涉及金額大、風險高（可能有點交爭議、隱藏債務等問題），
  實際出價前仍建議諮詢專業估價師或代標顧問。
- 部分地區或物件類型的歷史案例較少時，系統會誠實呈現較低的信心水準，
  而不是給出看似精準但缺乏依據的數字。
